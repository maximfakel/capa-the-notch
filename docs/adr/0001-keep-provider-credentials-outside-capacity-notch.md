# Keep Provider Credentials Outside Capacity Notch

Capacity Notch integrates only through Provider-owned interfaces: the official Codex App Server and Claude Code's official status-line JSON. A small status-line bridge persists only Claude's five-hour and seven-day percentages, reset times, and capture time; it deliberately discards all session data and never exposes credentials or an Anthropic network client to the app. This keeps authentication entirely inside each Provider, at the cost that Claude Capacity refreshes only while Claude Code runs and becomes visibly stale after five minutes.

**Amended 2026-09-23, recording ticket 13.** The status line runs only in a terminal; Claude Code's desktop app and VS Code extension start the same binary in a mode that has none. Capacity Notch therefore also runs Claude Code's own `/usage` command, no more often than every five minutes, and reads its printed percentages and reset times; the bridge stays as a live update where it runs, and the newer reading wins. This is still a Provider-owned interface — Claude Code authenticates and makes the request, and Capacity Notch reads no credential and contacts no Anthropic endpoint — so the decision above stands, and the cost it names is gone: Claude Capacity no longer depends on a Claude Code session being open. What it costs instead is a subprocess every five minutes, and a dependency on the wording of human-readable output, which is why output that no longer parses must surface as its own state.

**Amended 2026-10-02, adding OpenCode.** OpenCode Go reports its limits nowhere OpenCode itself owns: `opencode stats` sums local tokens and cost, and neither the TUI nor `opencode serve` exposes the plan's windows (anomalyco/opencode#42776 asks for it, unanswered). The only source is the undocumented `GET opencode.ai/zen/go/v1/usage`, which takes the person's API key. Decided with the author: OpenCode is the one exception to the rule above. Capacity Notch reads the key from OpenCode's own `~/.local/share/opencode/auth.json` at each request, keeps it nowhere — not in memory between requests, not in the Keychain, not in a setting — and sends it only to that one address, asking only for the percentages and reset times, no more often than every five minutes and when a person asks. Connecting OpenCode asks for consent first, saying exactly that, as Claude Code's connection does. Without the file there is nothing to read, and the surface says to sign in to OpenCode. The cost: the app now touches a credential, and depends on an endpoint OpenCode may change without notice, so an answer that no longer parses surfaces as its own state. A person pasting a key into Settings was considered and left out — it would make Capacity Notch a store of someone else's secrets.

**Amended 2026-10-03, after the rename.** The application became CapaTheNotch.app, and a person who followed the README has Claude Code's `~/.claude/settings.json` running the bridge from CapacityNotch.app — a path that stops Claude Code's status line, theirs too if it runs through the bridge, once the old bundle is gone. That file can hold credentials (an `env` block), so CapaTheNotch never opens it unasked. Once, on the first launch of an installed CapaTheNotch.app, and only where the bridge has left a reading in the application's own folder, it asks; after a yes it reads `settings.json` and `settings.local.json`, changes nothing but the old bridge's path to its own, keeps the file's link and permissions, and keeps nothing it read. Rewriting the path silently was the alternative, and would have been the application editing another program's credentials file without a word.
