# The Shelf and Clipboard History Keep Little, and Only in Memory

Clipboard history holds everything a person copies — passwords, tokens, private messages — which makes it the most sensitive data Capacity Notch would ever touch; the Shelf holds files dropped on the notch, which is almost harmless. Ticket 15 put them next after the calendar and asked for this record of what they may keep before any code. Decided with the author on 2026-09-30 (ticket 24).

They are two Modules, the Shelf Module and the Clipboard History Module, each with its own switch and both off until turned on (ADR 0003), so the Shelf can ship while the clipboard waits, and either can be off while the other is on. Neither writes anything to disk: what they hold lives in memory, goes when Capacity Notch quits, and goes at once when the Module is switched off. Copy Diagnostics and the log carry only counts and reason codes — never copied text, file names or paths (ticket 10).

The Clipboard History Module is for pasting again what was copied a little while ago; it is not an archive, so there is no search and nothing pinned. It keeps text only, and only what is copied after it is switched on: the last 20 Clippings by default, 50 or 100 if chosen in Settings, the oldest giving way. Each Clipping goes 24 hours after it was copied; that expiry is on by default and can be switched off. A text copied again rises to the top with a new 24 hours rather than appearing twice. A text longer than 100,000 characters is not kept at all, since a Clipping cut short would paste without its end and no one would notice. Choosing a Clipping puts it on the clipboard and nothing more; pasting is the person's own ⌘V, so the Module needs no Accessibility access. The history is not cleared on sleep or when the screen locks.

Some things are never kept, whatever the settings. Anything marked concealed, transient or auto-generated by the nspasteboard.org conventions (`org.nspasteboard.ConcealedType`, `org.nspasteboard.TransientType`, `org.nspasteboard.AutoGeneratedType`, and the older markers listed there), which is how 1Password, Enpass and KeePassXC mark a copied password. Anything copied while Passwords or Keychain Access was the frontmost application, because Apple's own apps set no marker; macOS does not say which application wrote to the clipboard, so the frontmost application at the moment of the change stands in, and Settings lets a person add applications of their own — a bank, a messenger, a password manager that may not mark its copies. And anything Capacity Notch itself put there: Dictation's text, a copied diagnostics report, a result copied from Dictation's history. Dictation keeps its own history, off unless asked for.

The Clipboard History is never shown in screen sharing or a recording, even when Settings lets the rest of the surface appear there: that switch exists to show Capacity on a call, not the token copied a minute ago. If macOS refuses to let the Module read the clipboard — macOS 15.4 introduced an alert for applications that read it programmatically and an `NSPasteboard.accessBehavior` to check the answer, and whether the alert is on by default was not settled when this was written — the Module says so in Settings, with a way to System Settings, and Copy Diagnostics carries the reason, as ADR 0004 asks of a Module that stops working.

The Shelf Module keeps references to files, never copies: a file set down on the way to somewhere else, not stored. A file moved or deleted since shows as unavailable. It holds up to 20 files, empty after Capacity Notch quits, and a file dragged out stays on the Shelf, since one file is often wanted in two places and removing it is a single action.

**Amended 2026-10-01 (ticket 25).** Some things dropped on the Shelf are not yet a file anywhere: an image dragged from a browser, a file promised by another application. The Shelf holds such an image in memory, like everything else on it, and it becomes a file only when it is dragged out, written wherever it is dropped; a promised file is received into a folder of the Shelf's own for a moment, taken into memory, and removed. An image left on the Shelf is lost when Capacity Notch quits, as the rest of the Shelf is. Writing such images where macOS saves screenshots was tried first and dropped the same day: it left files on the Desktop the person had not asked for.

The Shelf may also take in what is copied to the clipboard, on a switch of its own in Settings, off by default. It reads only the kinds of thing on the clipboard until one of them is worth taking: a screenshot taken to the clipboard (one item holding PNG and nothing else, named as macOS would have named the file); an image copied from a page or an application (its PNG, JPEG, WebP, HEIC or GIF, or its TIFF turned into PNG); or a file copied in another application — media or a document from a messenger, an attachment from mail — read into memory up to 50 MB, since it may sit in another application's cache, and kept as a reference past that. It never takes text, never a folder, never anything copied in Finder, where copying a file is a file operation rather than something to keep at hand, never anything marked concealed, transient or auto-generated by the nspasteboard.org conventions, and never anything copied while Passwords or Keychain Access is in front. If macOS refuses to let it read the clipboard, Settings says so and Copy Diagnostics carries `shelf-clipboard-refused` (ADR 0004).
